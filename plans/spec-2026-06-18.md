# Spec — `ralplan-consensus` Workflow (2026-06-18)

**Idea:** "lets create workflow from this ../pi-ralplan using workflow"

**Goal:** Encode the RALPLAN consensus planning protocol (Planner → Architect → Critic iteration loop, with optional Analyst spec phase) as a single workflow script persisted via `pi-subagentura`'s `workflow` tool. The script is invokable as `workflow("ralplan-consensus", args)` from any Pi session and produces a written, ADR-formatted plan in `plans/<planName>.md`.

## 2. Functional Requirements (FR)

- **FR-1. args shape.** `args` MUST accept:
  - `idea: string` (required)
  - `workingDir: string` (required, absolute path; `plans/` and `plans/drafts/` are created under it)
  - `specPath?: string` (skip Analyst if provided)
  - `deliberate?: boolean | null` (tri-state: true→DELIBERATE, false→SHORT, null→auto-detect)
  - `maxIterations?: number` (default 5, hard ceiling 100)
  - `planName?: string` (default `plan`)
- **FR-2. Phase sequence** (each phase = one `agent()` call):
  - (a) Analyst-spec *(only if no `specPath`)* → writes `plans/spec.md`
  - (b) Planner → writes `plans/drafts/plan_draft.md` (RALPLAN-DR Summary at top)
  - (c) Architect → writes `plans/drafts/architect_review.md`
  - (d) Critic → writes `plans/drafts/critic_review.md`, AND on ACCEPT verdict copies draft → `plans/<planName>.md`
  - (e) Consensus check → if dual-approve, finalize; else loop (b)–(e) until `maxIterations`
- **FR-3. Sequential ordering.** Planner → Architect → Critic is strictly sequential; never parallel (Architect must complete before Critic per RALPLAN protocol).
- **FR-4. Artifact paths** (relative to `workingDir`, forward-slash only — no `path.join`):
  - `plans/spec.md`
  - `plans/drafts/plan_draft.md` (overwritten each iteration)
  - `plans/drafts/architect_review.md`
  - `plans/drafts/critic_review.md`
  - `plans/<planName>.md` (only on success)
- **FR-5. RALPLAN-DR Summary** in plan draft: `**Mode:**`, Principles (3-5), Top 3 Decision Drivers, Viable Options (≥2 or explicit invalidation), Pre-Mortem (DELIBERATE only), Expanded Test Plan (DELIBERATE only).
- **FR-6. DELIBERATE detection.** Auto-detect by case-insensitive substring/word-boundary match against canonical signals from `pi-ralplan/pi/extensions/ralplan/prompts.ts:338-366`. **Bare `"auth"` is NOT a signal** (matches "author"); use `"authentication"` / `"authorization"` instead.
- **FR-7. Final plan ADR format:** `## Architecture Decision Record (ADR)` with `### Decision` / `### Drivers` / `### Alternatives Considered` / `### Why Chosen` / `### Consequences` (Positive/Negative) / `### Follow-ups`. Plus `## Task Breakdown` (exact file paths), `## Dependency Graph`, `## Acceptance Criteria per Task`, `## Risk Register`.
- **FR-8. Termination signal.** Log `PIPELINE_RALPLAN_COMPLETE` on success (canonical signal from `signals.ts:4`).
- **FR-9. Iteration loop.** Init `iteration=0`, `feedback=[]`. Loop Planner→Architect→Critic→parse→check. On dual-approve: break. On exit without: throw structured error with last verdicts + draft path.
- **FR-10. Verdict parsing.** Architect regex matches `**VERDICT: APPROVE|REVISION NEEDED**` (case-insensitive, whitespace-tolerant). Critic regex matches `**VERDICT: REJECT|REVISE|ACCEPT-WITH-RESERVATIONS|ACCEPT**`. Unparseable → `"UNPARSED"` → treated as iterate.
- **FR-11. Persona injection.** Each `agent()` call passes the corresponding role prompt as `persona:`. Role prompts inlined as string literals (OQ-2 resolution).
- **FR-12. Return value.** `{ planPath, planContent, iterations, mode, verdicts: { architect, critic }, feedback }` — JSON-serializable for the caller.

## 3. Non-Functional Requirements (NFR)

- **NFR-1. Determinism.** Script runs in `vm.runInNewContext`. NO `Date.now()`, `Math.random()`, argless `new Date()`, `fs`, `path`, `require`, `process`. All file I/O delegated to spawned sub-agents.
- **NFR-2. Concurrency cap.** Sequential phases → 3 + 1 agents × 5 iterations = 20 max, well under `MAX_TOTAL_AGENTS=1000`.
- **NFR-3. Reliability.** `agent()` returning `null` (engine `isError` path) → throw with phase name. Never silently continue.
- **NFR-4. Reproducibility.** Given the same args, the artifact filenames, verdict regex, iteration order are deterministic. Agent output reproducibility bounded by underlying LLM (out of scope).
- **NFR-5. Token budget.** Cap per-iteration feedback at 2000 chars via `extractFeedbackSection`. Respect `budget.remaining()` (engine throws when exhausted).
- **NFR-6. Self-contained script.** Single string parseable via `parseWorkflow()` (`src/workflow.ts:146-198`); `export const meta = {...}` must be a pure literal.
- **NFR-7. Naming.** `^[a-z0-9][a-z0-9-]{0,63}$`. Suggested: `ralplan-consensus`.
- **NFR-8. Isolation.** Default in-process (`startSubagentJob`); no `isolation: "process"` (no tmux attachability benefit; latency cost).
- **NFR-9. Path safety.** All paths via string concat, no `path.join`.

## 4. Implicit Requirements (IR)

- **IR-1.** Planner agent (first to touch `plans/drafts/`) must `mkdir -p` it. Analyst creates `plans/`.
- **IR-2.** If `args.specPath` provided but missing on disk → throw, don't silently run Analyst.
- **IR-3.** DELIBERATE→Critic reinforcement: Critic prompt explicitly told to reject missing pre-mortem / weak test plan.
- **IR-4.** Feedback accumulation: next Planner prompt gets BOTH Architect and Critic full reviews under `## Prior Feedback`.
- **IR-5.** Iteration labels: `label: "ralplan-planner-1"` etc. for TUI progress.
- **IR-6.** Mode sticky: DELIBERATE stays DELIBERATE across iterations (no demotion).
- **IR-7.** Verdict regex `/i` flag, whitespace-tolerant, conservative fallback.
- **IR-8.** Empty `args.idea` → throw before any agent spawn.
- **IR-9.** Synthesized Analyst persona (no source file in pi-ralplan for analyst role).
- **IR-10.** Return value JSON-serializable (caller is an LLM).

## 6. Architecture

```
Analyst (conditional: only when args.specPath is absent)
    │
    ▼
Planner  ──writes plans/drafts/plan_draft.md
    │
    ▼
Architect ──writes plans/drafts/architect_review.md     (SEQUENTIAL — never parallel with Critic)
    │
    ▼
Critic    ──writes plans/drafts/critic_review.md
    │       on ACCEPT: copies plan_draft.md → plans/<planName>.md
    ▼
parse verdicts → dual-approve?
    ├── yes → return result; log PIPELINE_RALPLAN_COMPLETE
    └── no  → append feedback, iteration++, loop (cap: maxIterations ?? 5)
```

## 8. DELIBERATE Mode Detection

Tri-state `args.deliberate`:
- `true` → DELIBERATE
- `false` → SHORT
- `null/undefined` → auto-detect by substring/word-boundary match

Signals (from `prompts.ts:338-366`): `security`, `credential`, `secret`, `password`, `token`, `migration`, `schema`, `database`, `production`, `destroy`, `delete`, `authentication`, `authorization`, `authorized`, `authorize`, `authorizing`, `compliance`, `PII`, `GDPR`, `HIPAA`, `public api`, `breaking change`. Word-boundary only: `rm`.

**Bare `auth` is NOT a signal** — matches "author"/"authentic" (deliberate exclusion per source).

## 9. API Surface

```ts
type RalplanArgs = {
  workingDir: string;
  idea: string;
  specPath?: string;
  deliberate?: boolean | null;
  maxIterations?: number;  // default 5
  planName?: string;       // default 'plan'
};

type RalplanResult = {
  planPath: string;
  planContent: string;     // empty (Critic writes to disk; script has no fs)
  iterations: number;
  mode: "SHORT" | "DELIBERATE";
  verdicts: {
    architect: "APPROVE" | "REVISION NEEDED" | "UNPARSED";
    critic:    "ACCEPT" | "ACCEPT-WITH-RESERVATIONS" | "REVISE" | "REJECT" | "UNPARSED";
  };
  feedback: string[];
};
```

## 10. Risks & Mitigations

| ID | Risk | Mitigation |
|----|------|------------|
| R-1 | Role prompt drift | Header comment cites source paths + last-synced date; resync procedure in CONTRIBUTING.md |
| R-2 | Verdict parsing fragility | Regex `/i` flag + whitespace tolerance + UNPARSED fallback |
| R-3 | Token exhaustion | `extractFeedbackSection` caps each feedback at 2000 chars; respect `budget.remaining()` |
| R-4 | Agent `null` returns | Throw with phase name; no in-place retry |
| R-5 | `vm` sandbox escape | `JSON.stringify(args.idea)` before prompt interpolation |
| R-6 | Missing `args.specPath` file | Trust caller; throw if invalid chars in path |
| R-7 | `MAX_TOTAL_AGENTS` cap | Not binding (20 agents max in default config) |
| R-8 | Critic fails to write final plan | Critic must end with `PLAN_WRITTEN: <path>` marker; script greps for it |
| R-9 | Distribution path | User-scoped via `save_workflow` (out of scope to bundle into package) |
| R-10 | Machine-readable consensus summary | Out of scope for v1 |

## 11. Acceptance Criteria (testable)

- **AC-1:** Workflow persists via `save_workflow("ralplan-consensus", text)`; `list_workflows` includes it.
- **AC-2:** Non-deliberate idea → SHORT mode (Planner prompt contains `**Mode:** SHORT`).
- **AC-3:** Ideas containing `migration`/`authentication`/`PII`/`schema`/`production`/`breaking change` → DELIBERATE mode.
- **AC-3.1:** Bare `auth` in "Add an author bio field" → SHORT (no false positive).
- **AC-4:** Mocked dual-approve exits at iteration 1; returns expected shape.
- **AC-5:** Mocked perpetual-reject exits at `maxIterations`; throws structured error with `.verdicts`/`.draftPath`/`.iterations`/`.feedback`.
- **AC-6:** Verdict regex matches canonical spellings + whitespace + case; UNPARSED fallback works.
- **AC-7:** Missing `args.workingDir` → throws before any `agent()` call.
- **AC-8:** Planner returning `null` → throws "Planner returned null at iteration N".
- **AC-9:** `maxIterations` default is 5.
- **AC-10:** Saved workflow invokable via `workflow("ralplan-consensus", args)`.
