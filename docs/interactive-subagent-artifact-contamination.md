# Interactive PR Review Incident: `lo.jsonl`

## Status

- Investigation goal: understand why the opened-PR review spawned empty, repeatedly-settled, and cancelled child runs.
- No production runtime code or package scripts were changed during the investigation.
- Option A is implemented in `vitest.config.ts`: Vitest clears `PI_SUBAGENTURA_CHILD` before loading tests.
- `lo.jsonl` is an untracked local parent-session log.
- The only requested artifact from this investigation is this document.

## Context

The parent session asked the interactive sub-agent system to review open PRs #74, #73, #69, #68, and #60. Each reviewer was launched in its own tmux-backed Pi session with an artifact directory containing:

- `events.ndjson` — lifecycle events
- `output.md` — current report
- `outputs/<event-id>.md` — immutable completion snapshots
- `session.jsonl` — child Pi session history
- `active-turn.json` — current lifecycle state

Relevant artifact IDs:

|  PR | Artifact ID        |
| --: | ------------------ |
| #74 | `740036cc3fdde6cc` |
| #73 | `adb71e316342b18e` |
| #69 | `c0894e488e57b954` |
| #68 | `559c73812113e7e9` |
| #60 | `97d1e972ced0df86` |

## Observed impact

The parent received multiple completion notifications for #73 and #69. Several completions had:

- `outcome=done`
- `source=agent_settled`
- `bytes=0`
- empty immutable output snapshots

The parent later cancelled child runs. This is separate from the test contamination: the environment leak explains false completions and artifact corruption, but the exact parent cancellation trigger was not established for every run. The actual reviewers did not produce usable PR reports.

## Timeline and correlation

1. The five reviewers were launched around the same time.
2. Reviewer #73 ran:
   - `npm ci --ignore-scripts`
   - `npm run typecheck`
   - `npm test -- --reporter=dot`
   - `npm run format:check`
3. Reviewer #69 ran:
   - `npm run typecheck`
   - `npm test -- --run`
   - additional diff and source checks
4. The extra lifecycle events in #73's artifact appeared immediately after its `npm test` command.
5. The extra lifecycle events in #69's artifact appeared immediately after its `npm test` command.
6. The parent poller read those events as real child completions and batched them into parent notifications.
7. The actual child sessions were later cancelled before writing final reports.

The clean reproduction produced short `turnId` values generated by fake harness sessions. In the live incident artifacts, the first false completion reused the real reviewer turn ID (`2167e9b0` for #73 and `9210fa60` for #69), because fake protocol handlers shared `active-turn.json`; later false completions used short fake IDs.

## Root cause

The interactive launch script exports these variables into the child Pi process:

```bash
export ARTIFACT_DIR=<live artifact directory>
export PI_SUBAGENTURA_CHILD=1
```

Those variables are inherited by every command the reviewer runs, including `npm test`.

The test suite loads `src/subagent.ts` through `createPiSessionHarness`. The extension checks `PI_SUBAGENTURA_CHILD` and registers `src/child-protocol.ts`. That protocol captures `ARTIFACT_DIR` and attaches lifecycle handlers to the fake test session.

Many test harnesses are created without an explicit `childArtifactDir`. In that case, the test harness temporarily changes neither inherited variable, so the child protocol writes to the reviewer's real artifact directory instead of a temporary test artifact.

The resulting flow was:

```text
interactive child starts
  -> PI_SUBAGENTURA_CHILD=1 and ARTIFACT_DIR=<live artifact>
  -> reviewer runs npm test
  -> Vitest creates fake Pi sessions
  -> src/subagent.ts enters child mode
  -> child-protocol.ts uses the live artifact
  -> fake turns append turn_started and completion events with source=agent_settled
  -> shared active-turn.json can make a fake settlement reuse the real turn ID
  -> output.md is empty for those fake turns
  -> parent poller delivers them as real completions
```

Relevant code locations:

- `src/interactive-tmux.ts` — launch script exports `ARTIFACT_DIR` and `PI_SUBAGENTURA_CHILD`.
- `src/subagent.ts` — enters child mode when `PI_SUBAGENTURA_CHILD === "1"`.
- `src/child-protocol.ts` — captures `ARTIFACT_DIR` and writes turn/completion events.
- `tests/helpers/pi-session-harness.ts` — only overrides child environment when `childArtifactDir` is supplied.
- `tests/pi-session-delivery.integration.test.ts` — contains harnesses both with and without `childArtifactDir`.

## Direct reproduction

Before Option A, the behavior was reproduced without changing source code:

```bash
LIVE=$(mktemp -d)
PI_SUBAGENTURA_CHILD=1 ARTIFACT_DIR="$LIVE" \
  npm test -- --run tests/pi-session-delivery.integration.test.ts
```

Result:

- 24 tests passed.
- The temporary live artifact received four `turn_started` / `agent_settled` pairs.
- Every generated completion snapshot was empty.

This matches the incident pattern in `lo.jsonl`.

## What was ruled out

- `triggerTurnOnComplete` alone was not sufficient; controlled runs with triggering enabled and disabled completed normally.
- Explicit `cli.mjs done 0` duplication was not the cause; it is idempotent by turn ID.
- Parent delivery batching was not the source of the events. It correctly delivered events already present in the artifact log.
- Empty output was not evidence of a successful empty review. It was produced by fake test sessions and later cancellation of the real reviewers.

## Immediate workaround

For reviewer sessions whose branch does not contain Option A, sanitize test commands externally:

```bash
env -u PI_SUBAGENTURA_CHILD -u ARTIFACT_DIR npm test -- --run
```

Use fresh sub-agent IDs and fresh artifact directories after cancelling the polluted runs. Do not truncate or rewrite existing append-only event logs.

This workaround is Unix-specific and only applies to the exact commands where it is used. It also does not protect arbitrary commands such as `npx vitest`.

## Implemented minimal fix (Option A)

Vitest now explicitly runs in normal parent mode, independent of the host environment:

```ts
delete process.env.PI_SUBAGENTURA_CHILD;
```

`ARTIFACT_DIR` remains available because terminal E2E fixtures may intentionally use it. The child-mode marker is the variable that causes `src/subagent.ts` to register the child protocol.

The fix provides these guarantees for Vitest commands using this config:

- Ordinary Vitest tests run as parent sessions.
- Child-protocol tests can explicitly set `PI_SUBAGENTURA_CHILD=1` and restore it afterward.
- Local macOS, Linux CI, and other Node-supported machines use the same behavior.
- No shell-specific `env -u` syntax is required.

The targeted integration suite was rerun with inherited child variables after the change: all 24 tests passed and the sentinel artifact received no lifecycle events. This remains narrower than the harness-level fix: alternate runners and direct programmatic harness use can still inherit ambient child mode.

## Longer-term hardening

The minimal Vitest fix prevents this repository's tests from contaminating artifacts. A stronger product-level fix would also prevent child-only control environment variables from leaking into arbitrary child tool processes:

1. Capture the artifact path during real child startup.
2. Use a process-local child-runtime marker or startup handshake instead of relying solely on inherited environment variables.
3. Make `cli.mjs` resolve its artifact directory from its own absolute path, allowing the child process to drop `ARTIFACT_DIR` before running tools.
4. Keep parent-side event validation as defense in depth, but do not discard valid empty completions merely because they are empty.

## Verification completed

The baseline and post-fix checks passed:

```text
npm run typecheck
npm test                         # 57 files, 1371 tests
npm run format:check
npm run pack:check
PI_SUBAGENTURA_CHILD=1 ARTIFACT_DIR=<temp> npm test -- --run tests/pi-session-delivery.integration.test.ts
```

The final targeted run passed all 24 tests with inherited child variables, and the temporary sentinel artifact remained untouched. Before Option A, the same command produced four empty completion pairs.
